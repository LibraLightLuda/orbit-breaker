# sol6.1에 전달할 사운드 구현 지시

2026-10-14: 아래 지시의 구현과 기술 검증을 완료했다. 결과와 남은 청취/실장치 한계는 [SOUND_IMPLEMENTATION_REPORT.md](SOUND_IMPLEMENTATION_REPORT.md)를 따른다. 이 문서는 최초 구현 지시의 기록이다.

---

`D:\Antigravity\NewProject`의 Orbit Breaker에 `docs/SOUND_DIRECTION_PLAN.md`의 사운드 디렉션을 구현해줘. 먼저 `AGENTS.md`, `docs/SURVIVAL_V3.md`, `docs/VALIDATION_V3.md`, `docs/ARTIFACT_RETENTION.md`와 현재 diff를 확인하고 기존 사용자 변경을 보존해줘.

목표는 정밀한 SF 기체·에너지 무장의 타격감과, 붕괴하는 전장에서 성장하며 버티는 분위기를 실제 플레이 사운드로 완성하는 것이야. BGM만 교체하거나 효과음 파일만 만들어 놓는 데서 끝내지 말고, 실제 사건 연결·겹침 제어·믹싱·검증까지 완료해줘.

1. 현재 SoundBank·모델 이벤트·공통 버튼·설정/저장 구조를 재사용해. 전투 규칙·피해·재생/붕괴·난수·쿨다운·입력·미션·보상·저장/고스트 형식을 임의로 바꾸지 마. 필요한 위치·종류·등급 문맥은 표시용 사건으로 최소한만 추가해.
2. 먼저 실제 게임에서 들을 수 있는 60~90초 대표 구간을 만들어. 음악 bed/drive/pressure, UI 확인, 자동포/명중, 돌진, 피격, 파츠 장착, 미션 성공, 낮은 체력/빠른 붕괴의 서로 다른 경고를 포함해. 품질 기준을 맞춘 뒤 세 전장·세 기체·모든 진화/아이템·파츠·미션·재해·메뉴/결과로 확장해.
3. 낮은 체력, 자연 붕괴 가속, 외곽 손상을 서로 다른 소리로 알려줘. 실제 모델 값을 읽고 임계치 진입/해제 지연, 반복 간격, 경고 우선순위와 ducking을 적용해. 위기 때 보상음과 대량 사격이 회피 경고를 가리지 않게 해.
4. 일시정지·강화·도감·음소거·웹 첫 입력/탭 복귀·모바일·관전 배속/seek를 처리해. 실제 보상 확정 전 성공음을 내거나 UI와 모델에서 같은 소리를 두 번 내지 마. 현재 전체 소리/배경 음악 설정과 옛 저장을 보존해.
5. 실제 사용 가능한 제작 수단으로 음악과 효과음을 만들고, 자산 manifest와 원본/권리 정보를 남겨. 최초 사용 합성/파일 로딩을 전투 프레임에 남기지 마. 단순 비프음 시제품을 최종 사운드 품질로 보고하지 마. 유료 결제·새 계정 가입·프로젝트 외부 업로드는 이 지시에 포함하지 않아.
6. 계획의 자동 회귀와 실제 청취 장면을 검증해. 기존 Dummy/음소거 검사는 소리 청취를 대신하지 않아. 사운드가 켜진 Windows/Web와 가능한 실제 모바일에서 확인하고, 불가능한 항목은 오디오 포함 재현 캡처와 미검증 사유를 남겨. 사람의 청취 수용을 자동 통과로 쓰지 마.
7. 동일 조건의 오디오 OFF/ON 성능을 측정하고, 기존 필수 검사·Windows/Web candidate 내보내기·실행·SHA-256 검증을 통과한 뒤에만 최신 배포본을 교체해. 성공 후 이전 세대와 임시 백업을 정리해 최신 검증 완료 한 세대만 유지해. 소스·설계·플레이어 저장/설정은 보존하고 정리 차단을 우회하지 마.
8. 구현·제작·회귀·청취·성능·배포·남은 한계를 구분한 보고서를 작성하고 `docs/VALIDATION_V3.md`를 실제 결과로 갱신해. 공개 사이트/릴리즈 게시와 원격 push는 별도 지시가 있을 때 진행해.

일반적인 음색 세부 조정·파일 구성·엔진 연결 선택은 계획의 기준에 따라 스스로 결정하고, 구현 도중 불필요한 승인 질문을 반복하지 말아줘. 작업 환경상 해결하지 못한 제작 품질이나 실장치 검증은 완료했다고 표시하지 말고 구체적으로 남겨줘.
