# ORBIT BREAKER 사운드 디렉팅 · 구현 기획서

작성일: 2026-10-13 · 대상: 현재 3.18.3 소스 · 상태: **구현·기술 검증 완료(2026-10-14) / 사람 청취 수용·실물 모바일 미검증**

구현 결과는 [SOUND_IMPLEMENTATION_REPORT.md](SOUND_IMPLEMENTATION_REPORT.md)를 따른다. 이 문서는 sol6.1이 실제 사운드 자산 제작, Godot 연결, 믹싱, 검증까지 수행하기 위한 실행 명세다. 현재 기능에 대한 관찰과 새로 제안하는 사운드 동작을 구분한다. 아래 시간·음량·임계치는 **사운드 연출의 초기 설계값**이며 게임 규칙 변경안이 아니다.

게임 규칙은 [SURVIVAL_V3.md](SURVIVAL_V3.md), 배포 결과는 [VALIDATION_V3.md](VALIDATION_V3.md), 보관 규칙은 [ARTIFACT_RETENTION.md](ARTIFACT_RETENTION.md)가 우선한다. 시각 정체성은 [ART_DIRECTION_PLAN.md](ART_DIRECTION_PLAN.md)의 ‘닫힌 장갑 면·분리된 에너지 코어·동심 궤도’를 이어받는다. 과거 아트 문서의 플랫폼 설명 대신 현재 모바일 조작·화면 규칙을 따른다.

## 1. 디렉션의 핵심

**“정밀한 기체를 조종하며 무장을 키우는 쾌감, 그 바깥에서 점점 빠르게 무너지는 우주.”**

플레이어의 기체는 단단하고 정확하게, 적과 우주 재해는 불안정하고 거대하게 들린다. 획득·장착·진화는 성장한 결과를 분명하게 들려준다. 후반 긴박감은 모든 소리를 크게 만드는 방식보다 리듬 밀도, 좁아지는 간격, 불안정한 질감, 음악의 여백으로 만든다.

장르는 **어두운 SF 전자음악 + 절제된 산업 타악 + 장갑/에너지 기계음**이다. 정밀한 현재 아트와 어울리는 입체적 질감이 필요하다. 긴 멜로디나 보컬이 전투 정보를 덮지 않도록 한다. 진공 속 외부 현상은 함체 진동·센서 경고를 소리로 번역한 미술적 해석으로 다룬다.

| 소리의 영역 | 플레이어가 느껴야 할 것 | 공통 재료와 문법 |
| --- | --- | --- |
| 아군 기체·UI | 정확함, 조작 신뢰, 손에 잡히는 기계 | 짧은 금속 접점, 정돈된 전자 펄스, 선명한 시작점 |
| 무기·타격 | 발사 → 접촉 → 파괴가 구별됨 | 추진 압력, 금속/결정 파쇄, 에너지 방전, 짧은 저역 몸통 |
| 획득·성장 | 회수했다, 장착됐다, 한 단계 강해졌다 | 흡착 → 잠금, 상승하는 음형, 성장 규모에 따른 화성 확장 |
| 적·보스 | 외부에서 조여 오는 압박 | 불규칙한 펄스, 어긋난 배음, 무거운 기관 공명 |
| 붕괴·재해 | 선체 밖의 질서가 망가짐 | 분절된 틱, 주기 불안정, 금속 응력, 공간이 접히는 흡입음 |

기억할 소리 세 가지를 먼저 만든다. **돌진의 압축·분출, 파츠의 장착 잠금, 치명적 선체 상태의 코어 경보**다. 음악을 꺼도 이 세 가지의 역할을 알아야 한다.

전체 범위를 줄이는 선택지는 대표 전투 60~90초만 먼저 완성하는 것이다. 기본 실행은 그 구간의 품질을 확인한 뒤 이 문서의 전체 범위를 끝내는 순서다.

## 2. 현재 구현에서 확인한 출발점

| 현재 사실 | 근거 | 이번 작업에서 보완할 점 |
| --- | --- | --- |
| 14개 효과음 cue, 10개 재생 슬롯, 22,050Hz 모노 합성 | [sound_bank.gd](../scripts/sound_bank.gd) | 종류별 재질, 우선순위, 겹침 제어, 위치 정보 |

| 효과음은 최초 사용 때 합성하고 캐시 | `SoundBank.play()` | 전투 중 첫 재생의 생성 비용을 출격 전으로 이동 |

| 일반 버튼은 `select`를 재생 | `main.gd._button()` | 포커스, 확인, 뒤로, 실패, 출격 구분 및 중복 제거 |

| 지속 경고를 구동할 모델 값이 이미 존재 | `hp/max_hp`, `decay_rate()`, `boundary_damage_rate()`, `net_hull_rate()` | 체력·붕괴·외곽 위험을 서로 다른 원인으로 전달 |
| 기존 렌더/성능 검사 일부는 음소거 또는 Dummy 오디오 사용 | `tests/test_uiux.gd`, `tests/test_art.gd`, 검증 스크립트 | 소리가 켜진 실제 믹스·성능·플랫폼 검증 추가 |

소스에서 현재 구조를 확인한 결과다. 기존 음색의 실제 청취 평가는 이번 기획에서 수행하지 않았다. 현재 배포 문서의 통과 수치도 새 오디오 작업의 통과 근거가 될 수 없다.

범위는 3기체, 3전장, 일반 적 4종과 정예/지휘체, 12무기 진화, 12아이템×C/B/A, 3파츠, 4기체 조합 I/II, 10미션, 공통 이벤트 4종, 메뉴·결과·관전이다. 현재 입력 방식, 점수·경험치·피해·쿨다운·드롭·미션·저장·고스트 형식을 보존한다.

## 3. BGM: 한 곡의 성장과 전장별 공간감

### 3.1 음악의 재료와 제작 단위

기본 템포는 **120 BPM, 4/4**. 전투 공통 조성은 D minor를 초기안으로 삼는다. 주 모티프는 `D–F–A`의 짧은 상승형으로 정하고 메뉴, 성장, 돌파에서 변형한다. 위험 알람은 고정된 음높이·리듬을 사용하여 음악 조성에 따라 정체성이 바뀌지 않게 한다.

전투 음악은 길이가 같은 **96초/48마디의 세 stem(동기화된 분리 트랙)**으로 만든다. 박자·루프 경계·샘플 수를 일치시키고 세 stem을 함께 재생하되 볼륨으로 밀도를 바꾼다. 상태가 바뀔 때 곡을 처음부터 다시 시작하지 않는다.

| 자산 ID | 길이·형태 | 제작 지시 |
| --- | --- | --- |
| `mus_menu` | 64초 루프 | 넓고 얕은 패드, 멀리 들리는 기계 펄스, 주 모티프의 느린 단편. 출격 준비·도감·기록에서 공유 |
| `mus_battle_bed` | 96초 동기 stem | 공간감, 낮은 전자 베이스, 제한된 화성. 단독으로도 음악이 성립 |
| `mus_battle_drive` | 동일한 96초 | 정교한 타악·8분음표 추진 리듬. 자동포보다 둔한 어택으로 역할 분리 |
| `mus_battle_pressure` | 동일한 96초 | 16분음표의 일부를 비워 만든 긴장 패턴, 금속 공명, 불안정한 배음. 단독 최고음량으로 튀지 않음 |
| `amb_ring` | 약 32초 루프 | 규칙적인 센서 주사, 먼 궤도 구조물의 공명. 개별 적 접근음처럼 오인시키는 신호는 제외 |
| `amb_storm` | 약 32초 루프 | 얇은 전기 잔광, 이온성 입자 질감. 실제 번개 예고의 충전 패턴은 사용하지 않음 |
| `amb_forge` | 약 32초 루프 | 느린 금속 비틀림·열압력·낮은 기계 진동. 폭발 직전 예고음과 구별 |

첫 납품은 음악 4개와 전장 환경음 3개다. 전장별로 곡을 세 벌 만들기보다 공통 주제에 다른 환경음과 믹스를 입힌다. 보스·진화·결과는 짧은 stinger(상태 전환 음악)로 제작한다. 레이어를 쌓은 최종 믹스에서 저역·공간감·경고 식별을 함께 점검한다.

### 3.2 음악 상태와 전환

아래 dB는 각 자산의 기준 믹스에 더하는 **상태별 상대 게인**이다. 기본 자산 음량과 사용자 슬라이더는 별도로 적용한다.

| 상태 | 조건 | bed / drive / pressure | 전환과 감정 |
| --- | --- | --- | --- |
| 메뉴·준비 | 메뉴 계열 화면 | `mus_menu`만 | 준비된 장비 앞의 차분한 긴장 |
| 적응 | 전투 0~50초 | 0 / −12 / OFF | 기체·획득음이 먼저 들림 |
| 교전 | 50~150초 | 0 / −6 / −18 | 미션과 성장에 추진력 부여 |
| 압박 | 150~300초 | 0 / −3 / −12 | 정예·적 밀도 상승을 받침 |
| 한계 생존 | 300~480초 | 0 / 0 / −6 | 5분 돌파는 계속 싸우는 짧은 성취 |
| 말기 붕괴 | 480~600초 | 0 / 0 / −3 | 여백은 유지하고 리듬의 긴장만 증가 |
| 지휘체 교전 | 실제 살아 있는 지휘체 존재 | 현재 단계 위에 drive 최대 0, pressure 최대 −3 | 첫 진입 stinger 1회. 두 번째 지휘체 출현마다 곡 재시작 금지 |
| 낮은 선체·고속 붕괴 | §6의 경고 상태 | 현재 BGM 전체 −3~−6 | 경고가 전면. 음악은 빨라 보일 수 있어도 실제 재생 속도·피치 변경 없음 |
| 강화 선택·일시정지·전투 중 도감 | 전투가 정지한 화면 | drive/pressure 정지, bed −10 또는 정지 | 전투 루프 위치 보존. 위험 타이머 정지. UI음은 즉시 사용 가능 |
| 결과 | 실제 `won/lost`, `end_reason` 확정 | 전투 루프 0.4초 fade-out | 결과 stinger 뒤 메뉴 bed를 낮게 복귀 |

일반 상태 전환은 다음 마디부터 1~2마디 crossfade한다. 체력 경고·피격·재해의 즉시 소리는 음악 박자를 기다리지 않는다. 보스 종료/위험 해제는 2초 안정 후 천천히 원래 믹스로 돌아간다. 5분 시각만으로 승리음을 내지 않고 모델의 실제 `milestone`/돌파 상태를 사용한다.

전투 시간이 멈추면 음악도 전투 진행을 앞질러 가지 않는다. 모든 플랫폼에서 안정적인 stem 일시정지/동기화가 먼저 입증되어야 한다. 구현 방식은 현재 Godot 기능 중 가장 간단한 것으로 선택한다.

## 4. 효과음 제작표

아래 ID는 **새 사운드 계약 이름**이다. 현존하는 모델 이벤트 이름과 다르며 §8에서 연결한다. 대괄호의 변형은 같은 계열의 실제 변형 파일/설정으로 관리한다. 고빈도 소리는 3~5가지 자연스러운 변형을 먼저 만들고, 낮은 빈도의 알림은 고유한 한 소리로 시작한다. 파일 수를 늘리기 위해 모든 ID를 독립 녹음으로 만들 필요는 없다.

### 4.1 UI·조작

| Cue ID | 재생 시점 | 소리·길이 | 제어 |
| --- | --- | --- | --- |
| `ui_focus` | 사용자의 마우스/키보드로 선택 대상이 바뀜 | 가벼운 접점+공기 없는 짧은 틱, 30~50ms | 80ms 간격, 자동 포커스/메뉴 재생성은 무음, 터치 hover 생성 금지 |
| `ui_confirm` | 일반 버튼의 유효한 확정 | 접점 두 층이 맞물리는 클릭, 70~110ms | 키보드·마우스·터치 중복 경로에서도 1회 |
| `ui_back` | 뒤로/닫기/취소 성공 | 낮아지는 짧은 해제음, 80~140ms | 확인음과 동시 재생 금지 |
| `ui_change` | 기체·전장·난이도·페이지 값 변경 | 정밀 셀렉터/래치, 60~100ms | 같은 값 재선택은 무음 |
| `ui_denied` | 잠금 선택·자원/쿨다운 부족에 대한 실제 피드백 | 둔한 짧은 두 펄스, 120~180ms | 누르고 유지해도 최대 초당 2회, 경고처럼 크지 않게 |
| `ui_toggle[on/off]` | 소리·음악 등 설정 확정 | 상행/하행 2음, 90~150ms | 전체 음소거 ON 이후는 소리 금지. OFF 해제는 1회 허용 |
| `ui_launch` | 출격 확정 | 시스템 잠금 → 코어 충전 → 짧은 추진, 0.7~1.0초 | 게임 시작이나 입력을 지연시키지 않음 |
| `ui_pause[open/close]` | 실제 정지/복귀 전환 | 얇은 통신 게이트, 100~170ms | 기존 ESC·버튼·모바일 경로 공통 |
| `ui_upgrade_open` | 실제 강화 선택 화면 1회 열림 | 구조가 펼쳐지는 3음, 0.35~0.5초 | XP 획득음과 중복 강조 금지 |
| `ui_upgrade_apply` | 강화가 실제 적용됨 | 장비 체결+짧은 상승, 0.25~0.4초 | 카드 클릭음·모델 upgrade 중 하나가 대표 발성 |
| `ui_record`, `ui_achievement`, `ui_discovery` | 신기록/새 업적/새 발견 확정 | 각각 성취 3음/짧은 인장/정보 등록, 0.3~0.8초 | 과거 목록 열람 때는 무음, 동시 알림은 묶어서 1회 강조 |
| `ui_save_error` | 저장 실패 상태로 새로 진입 | 낮은 중립적 단음, 0.2초 | 재시도마다 반복 금지, 화면 안내 유지 |

스킬 버튼은 성공 시 `ship_dash`/`ship_overdrive_start`가 조작 피드백을 담당한다. 버튼 클릭과 스킬 소리를 두 번 강조하지 않는다. 취소된 터치, 포커스 상실, 메뉴 전환은 스킬 성공음을 내지 않는다.

파츠는 **출격 중 장착 재료**다. 새 출격까지 영구 보유하는 듯한 계정 해금 fanfare를 쓰지 않는다. 현재 조합 ID `lancer/battery/aegis/trinity`는 구현 시 `expedition.gd`의 실제 키를 다시 확인해 I/II를 전수 연결한다. 조합명을 바꾸거나 새 조합을 만들지 않는다.

소멸 경고는 개체당 한 번, 전체로는 2초 간격으로 제한한다. 한 번에 가까운/추적 중인 대상 하나를 대표하며 다른 개체의 시각 안내는 유지한다. 위험 경고 중에는 소멸 소리를 생략한다. 시간은 실제 전투 시간을 사용하고, 필드 수명 35초/45초와 남은 10초 기준을 바꾸지 않는다.

## 5. 전장의 공간감과 정보 배치

UI·획득·성장·체력·붕괴 경보는 중앙에서 들린다. 무기 발사·폭발·적 공격·재해는 화면상의 상대 위치로 부드럽게 좌우를 나눈다. 방향을 소리로 제공하되 기존 화살표·예고 영역·숫자 안내를 유지한다.

- 화면 중앙에서 가장자리까지 pan을 최대 ±0.65 정도로 제한한다. 한쪽 이어폰에서 정보가 완전히 사라지는 hard pan은 사용하지 않는다. 좌표는 현재 카메라와 화면 변환을 사용한다.
- 거리 감쇠는 전투 장식음에 강하게, 회피에 필요한 가까운 공격 예고에는 약하게 적용한다. 화면 밖 보스 접근은 시스템 서명을 중앙에서 한 번, 이후 위치음은 실제 위치가 있을 때만 사용한다.
- 같은 폭발이 여러 명을 맞혀도 폭발음은 공격 1회 기준이다. 명중·처치는 가까운/중요한 대상부터 제한한다.
- 전장 환경음은 실제 경고의 음형을 흉내 내지 않는다. 플레이어가 반응해야 할 소리를 배경 장식으로 쓰지 않는다.
- 리버브 꼬리는 UI 0~80ms, 일반 타격 80~250ms, 큰 재해/보스 0.4~0.9초를 초기안으로 한다. 고밀도에서 저역과 긴 잔향이 쌓이면 먼저 줄인다.

## 6. 체력·붕괴·외곽의 긴박감

### 6.1 원인을 분리하는 입력

사운드 계층이 읽는 값은 다음으로 한정한다. 모델의 수치를 재계산하거나 HP를 예측해 판정을 바꾸지 않는다.

- `H = hp / max(max_hp, 1)` — 남은 선체 비율.
- `D = decay_rate() / max(max_hp, 1)` — 자연 붕괴가 초당 최대 선체에서 차지하는 비율. 수리·외곽 손상과 구분한다.
- `N = max(0, -net_hull_rate()) / max(max_hp, 1)` — 현재 순손실의 보조 정보. 흡수막으로 손실이 가려지는 상황을 구별한다.
- `boundary_layer(player)`, `boundary_damage_rate()` — 실제 외곽 위험. 자연 붕괴 레이어에 합산하지 않는다.

`hp / 손실률`을 남은 생존 시간으로 단정해 경보를 울리지 않는다. 전투 피해·재생·흡수막 변화로 오해가 생긴다. 실제 600초 종료까지 남은 시간만 별도 확정된 시간 신호로 사용할 수 있다.

### 6.2 선체 경고: “내 기체가 얼마 남지 않았다”

| 단계 | 진입 조건 | 소리 | 해제 조건 |
| --- | --- | --- | --- |
| 정상 | H > 0.30 | 경고 없음 | — |
| 주의 | H ≤ 0.30이 0.4초 유지 | `warn_hull_low`: 코어 접점의 짧은 2연타. 진입 1회, 이후 3초 간격 | H ≥ 0.36이 1.5초 유지 |
| 위험 | H ≤ 0.15이 0.2초 유지 | `warn_hull_critical`: 더 건조한 2연타, 약 1.2초 간격 | H ≥ 0.20이 1.5초 유지하면 주의로 |
| 붕괴 직전 | H ≤ 0.07 | 같은 위험 음색의 간격을 0.75초까지 축소 | H ≥ 0.10이 1.5초 유지하면 위험으로 |

단계는 가장 높은 위험 하나만 재생한다. 낮은 HP 상태에서 회복이 시작되어도 충분히 회복되기 전에는 ‘안전’을 암시하지 않는다. 최대 HP 변동·출격 초기화도 비율과 상태 전환으로 처리한다. 회복 후 해제음은 작게 한 번만 허용하고, 외곽/재해가 여전히 위험하면 안전한 승리 화음을 쓰지 않는다.

### 6.3 자연 붕괴 경고: “세상이 무너지는 속도가 빨라졌다”

| 단계 | 초기 진입 임계치 | 소리·음악 | 해제/안정화 |
| --- | --- | --- | --- |
| 배경 | D < 0.02/초 | 별도 붕괴 경고 없음 | — |
| 가속 | D ≥ 0.02/초가 0.8초 유지 | `warn_decay_rise` 1회+낮은 기계 틱의 `warn_decay_bed`, pressure stem을 최소 −9dB까지 | D < 0.017/초가 2초 유지 |
| 고속 | D ≥ 0.04/초가 0.8초 유지 | 분절 간격 1.2→0.6초, 거친 응력 질감. pressure 최소 −3dB | D < 0.034/초가 2초 유지하면 가속으로 |

틱 속도는 D에 따라 위 범위 안에서 완만하게 보간한다. 임계치마다 새로운 사이렌을 추가하지 않는다. 한계치 변화는 기체 3종·최대 HP 강화·전장 3종·난이도 4종·붕괴 완화 구간을 실제 재현해 조정한다. 시간만으로 가속을 판정하지 않아 용광로의 더 빠른 붕괴와 보스 처치/매분 완화를 반영한다.

흡수막이 켜져 N이 0이면 붕괴의 환경 질감은 낮게 남기되 ‘지금 선체가 손상 중’인 충격음을 내지 않는다. 수리로 N이 0이어도 D 자체가 높다면 ‘외부 붕괴 속도’의 소리는 유지할 수 있다. 선체 위험 경보가 활성화되면 붕괴 틱은 최소 6dB 낮추거나 리듬을 빼고 질감만 남긴다. BGM OFF에서도 붕괴 정보는 Warnings 버스에서 들려야 한다.

### 6.4 외곽·재해·종료가 겹칠 때

`warn_boundary_enter/deep/return`은 경계를 건드릴 때마다 울리는 충돌음이 아니라 위험층 변경을 알리는 계기판 신호다. 진입/심화는 0.3초 유지, 복귀는 0.6초 유지 뒤 한 번 알린다. 외곽 2/3층은 낮은 기체 손상과 구별되는 짧은 하행 스캔이다. 지속 외곽 손상에 기존 `boundary_hit`를 0.65초마다 그대로 더하면 경보가 과밀해지므로, 새 경계 신호와 체력 경보가 대표하도록 재매핑한다.

600초 강제 종료는 HP가 높아도 도래한다. `warn_final_collapse`를 **실제 전투 590초에 한 번**, 597/598/599초에는 짧은 tick으로 알린다. 일반 재해 countdown과 겹치면 즉시 회피 가능한 재해가 우선이고, 종료 경고는 한 번의 짧은 보조음으로 축약한다. 음량을 계속 올리거나 플레이 입력을 막지 않는다.

## 7. 믹싱·동시 재생·청취 피로

### 7.1 버스와 우선순위

최소 구성은 `Master → Music / Ambience / Combat / Feedback / UI / Warnings`다. 사용자는 **전체·배경음악·효과음** 3개 음량을 조절한다. Ambience/Combat/Feedback/UI/Warnings는 효과음 조절을 따른다. 기존 전체 소리/배경 음악 ON/OFF는 유지한다. 세부 버스별 슬라이더·EQ·환경 프리셋은 첫 구현 범위에 넣지 않는다.

| 우선순위 | 대표 소리 | 포화 상태에서의 처리 |
| --- | --- | --- |
| P0 | 즉시 재해 예고, 실제 치명적 선체 경보, 결과 전환 | 보호 슬롯 사용, 하위 발성을 중단 가능 |
| P1 | 플레이어 피격·방벽 반격, 돌진·오버드라이브 발동, 보스 위험 전환 | P2~P4보다 우선. 재해 경고를 끊지 않음 |
| P2 | 파츠·미션 성공·무기/기체 진화·돌파 | 1개 대표음만, 중요 알림은 제한된 지연 허용 |
| P3 | 일반 사격·명중·파괴·UI 포커스·XP 회수 | 집계/생략. 사라진 전투 소리를 나중에 몰아서 재생하지 않음 |
| P4 | 엔진·환경·비필수 보조 틱 | 먼저 낮추거나 중지 |

활성 화면의 유효한 UI 확정은 별도 UI 슬롯 1개를 확보한다. 잘못 눌렀다는 피드백이 대량 발사음 때문에 사라지지 않게 한다. 전체 one-shot 최대 16개, 그중 경고 2개·UI 1개를 보장한다. music 3 + ambience 1 + engine 1 + 전환용 1로 지속 재생 최대 6개, 전체 최대 22개를 초기 예산으로 삼는다. 붕괴 bed가 필요하면 환경/엔진 슬롯을 공유하거나 대체해 이 예산을 유지한다.

동일 우선순위에서는 화면 가까이 있고 새로 발생한 명확한 사건을 우선한다. 경고가 2개를 초과하면 실제 회피 시점이 가까운 재해 → 치명적 선체 → 일반 재해 예고 → 외곽 심화 → 붕괴 가속의 순서로 정리한다. 하위 경고의 시각 표시는 그대로 유지한다. 치명적 선체 경보는 첫 진입 후 최대 0.3초 안에 들릴 짧은 슬롯을 보장하고, 지속 반복은 가까운 공격 예고가 잠깐 양보받을 수 있다.

### 7.2 Ducking과 음량

- P0 경고/중요 피격 시 BGM −4dB, 일반 전투 −3dB, 환경 −6dB를 20~40ms에 걸쳐 낮추고 약 300ms 유지 후 500ms에 복구한다. 계속 위험하면 각 경고 사이에 음량이 펌핑되지 않게 유지한다.
- 진화·돌파는 BGM −3dB, 전투 −2dB로 최대 0.8초 양보받는다. 위험 경보가 있으면 성장음의 강조를 먼저 줄인다.
- 여러 duck 요청은 합산하지 않고 가장 강한 목표치 하나를 적용한다. 끝날 때 원래 사용자 음량으로 복귀한다.
- 전투 음악 세 stem을 모두 켠 기준 믹스는 약 −20~−18 LUFS-I부터 청취한다. 최종 통합 스트레스 캡처는 true peak −1dBTP 이하를 목표로 두고 클리핑과 과도한 제한기 작동을 확인한다.
- 아주 짧은 UI/타격음은 LUFS-I 수치만으로 맞추지 않는다. `ui_confirm`과 `weapon_cannon`을 기준 소리로 삼아 실제 믹스에서 상대 크기·어택·잔향을 맞춘다. 파일마다 peak 0dB로 일괄 정규화하지 않는다.
- 경고는 리듬·음색·주변 소리의 양보로 알아듣게 한다. 강한 고역 비프와 초저역만으로 긴박감을 만들지 않는다. 모노·휴대폰 스피커에서도 중역의 식별점이 남아야 한다.

수치는 납품 목표이며 현재 달성값이 아니다. 사람 청취에서 음악이 시끄럽거나 경고가 피곤하면 우선 마스킹과 반복을 조정하고, 임계치 변경 근거를 남긴다.

### 7.3 겹침의 대표 사례

1. 파츠 하나로 여러 기체 조합이 완성됨: 파츠 잠금음 1회 + 가장 높은 `growth_hull` 1회. 업적/도감/초과 점수의 큰 알림음은 생략한다.
2. 보스 처치·미션 성공·레벨업이 한 프레임: 보스 코어 파괴를 즉시, 가장 중요한 성장음을 최대 0.8초 뒤. 강화 화면은 실제 진입음을 1회만 낸다. 보상음을 모두 줄 세우지 않는다.
3. 6% HP·외곽 3층·번개 충전: 가까운 번개 예고와 선체 경보를 보장. 외곽/붕괴는 배경 질감으로 낮추고 XP·만료 알림 생략.
4. 흡인으로 경험치·아이템·파츠 동시 회수: XP는 집계, 파츠를 대표, 일시 아이템은 가장 높은 등급 하나의 짧은 끝음으로 통합. 실제 게임 보상은 모두 유지.
5. 사망 프레임: 미션 실패·만료·체력 반복음을 중단하고 결과 전환 1회. 직전 재해의 긴 잔향은 100~250ms에 정리.

보상 지연 큐는 최대 2개, 최대 대기 0.8초다. 대기 중 화면이 결과/메뉴로 바뀌면 폐기한다. 정지 화면 진입으로 보류하는 경우에도 중복 재생하지 않는다. 급박한 사건은 지연 큐에 넣지 않는다.

### 8.2 사건의 출처와 중복 방지

| 현재 출처 | 새 연결 원칙 |

| `evolution/hull_evolution/boss_down/milestone` | 서로 다른 성장·처치·돌파 cue, 실제 성공 확정에 연결 |

| HP/붕괴/외곽/준비 완료 | 이전 값→현재 값의 전이, 별도 표시 상태에서 히스테리시스·재알림 관리 |
| `won/lost`와 `_finish_run()`/결과 화면 | 모델 확정과 결과 UI 둘 중 한 곳을 최종음의 소유자로 지정 |

위치·종류·등급을 기존 `events: Array[String]`만으로 알 수 없는 사건은 **해당 성공 지점에서 필요한 문맥을 한 번 전달**한다. 필요하면 일시적인 `audio_events` 배열에 `{cue, source_id, position, variant}` 정도의 최소 데이터를 넣고 현재 `run.events` 소비 지점에서 함께 비운다. 기존 사건 배열과 저장/고스트 스키마를 통째로 바꾸지 않는다. 새 문맥을 연결한 사건은 옛 alias가 다시 울리지 않게 한다.

지속되는 `effects` 배열을 매 프레임 훑어 같은 시각 효과를 새로운 사건으로 재생하지 않는다. 음소거·프레임 생략·관전 seek 이후에도 과거 사건을 소리로 쏟아내지 않는다. 소리 생성을 위해 게임 RNG, 아이템 RNG, 미션 RNG를 소비하지 않는다. 현재 합성의 전역 `randf_range()` 의존은 오디오 전용 난수나 미리 만든 변형으로 격리한다.

### 8.3 시간·화면·웹·관전

- 전투 경고/만료/미션/쿨다운 판단은 모델의 전투 시간, UI hover 쿨다운은 UI 시간을 쓴다. pause·강화·도감·초점 상실에서 전투 소리와 예약 사건을 정리하고, 복귀 시 현재 상태부터 재동기화한다.
- 전체 음소거 중에도 상태 전이는 갱신한다. 다시 켰을 때 과거 획득/경고를 재생하지 않는다. 현재 치명적 상태가 계속된다면 현재 상태의 경고 한 번으로 재진입한다.
- 웹 첫 진입은 실제 사용자 입력 이후 소리가 시작되는 경로를 검증한다. 최초 무음/지연으로 버튼 입력을 재실행하거나 출격을 중복시키지 않는다. 탭 복귀·화면 회전·오디오 재개에서 루프 2개가 중복되지 않아야 한다.
- 고스트는 기본적으로 **관전 BGM + UI 소리**만 제공한다. 복원만으로 발사·획득·업적·미션 보상음을 새로 만들지 않는다. 과거 경로 고스트도 동일하다. 이번 범위에 정확한 전투 오디오 재연용 저장 스키마를 추가하지 않는다.
- 관전 1/2/4배속·앞뒤 seek는 BGM pitch와 UI음을 배속하지 않는다. 관전 일시정지는 BGM을 낮추고 보류 one-shot을 폐기한다. 관전 종료 후 실제 출격의 경고 상태를 초기화한다.

### 8.4 설정·저장

기존 `muted/music`는 그대로 해석한다. 새 음량 값은 누락 시 1.0, 유효 범위 0~1로 보정하고 손상/잘못된 타입은 기본값으로 복구한다. 기본 믹스 자체를 적절한 크기로 제작하므로 1.0이 과도한 출력을 뜻하지 않게 한다. 새 필드 때문에 기록 파일 버전을 불필요하게 올리거나 옛 프로필을 덮어쓰지 않는다. 음량 변경도 현재의 정상 저장·실패 복구 경로를 이용한다.

모바일 설정은 기존 작은 화면 배치 원칙 안에 들어가야 한다. 세부 기능을 늘려 스크롤·조작 가림 문제를 다시 만들지 않는다. 효과 줄이기를 오디오 음소거로 해석하지 않는다.

## 9. 자산 제작·납품·예산

런타임 경로는 `assets/audio/music`, `ambience`, `ui`, `combat`, `feedback`, `warnings`로 나눈다. 원본 편집 프로젝트·합성 스크립트·제작 메모는 `audio_source/`에 둔다. 원본은 게임 자산의 제작 소스이며 배포 세대 백업으로 사용하지 않는다.

- 음악/환경 원본: 48kHz, 24bit 또는 float WAV. 런타임 음악/환경: 루프 경계가 확인된 Ogg Vorbis stereo를 기본안으로 사용한다. import 후 실제 포맷·loop 구간·위상 동기화를 확인한다.
- 짧은 효과음: 48kHz mono WAV를 기본으로, 고유한 폭/공간감이 필요한 결과음만 stereo 허용. 실제 배포 용량과 로딩 시간을 측정해 압축을 선택한다.
- 모든 자산은 앞뒤 클릭·DC 오프셋·잘린 잔향·불필요한 선행 무음이 없어야 한다. 음악 stem은 같은 길이와 같은 시작점, 환경 loop는 접합부가 들리지 않아야 한다.
- 최초 출격 전에 필요한 자산을 준비한다. 전투 프레임에서 파일 읽기·파형 합성·새 AudioStream 생성 금지. 무제한 노드 생성 없이 정해진 풀을 사용한다.
- 초기 예산: 새 압축 오디오 다운로드 15MiB 이내, 활성 디코딩/PCM 추가 메모리 약 32MiB 이내, one-shot 16개·지속 6개 이내. 예산 변경은 실제 수치와 품질 이유를 기록한다.
- `audio_source/manifest.json`에 cue/variant, 런타임 경로, 길이, 채널·샘플률, loop, 기준 gain, 우선순위·최소 간격, 제작 방식·권리 근거·수정 내역을 기록한다. 내용 구조를 불필요한 범용 엔진으로 만들지 않는다.

sol6.1은 먼저 실제 사용할 수 있는 제작 도구와 자산을 확인한다. 독자 합성·직접 제작을 기본으로 하고 외부 자산을 쓰면 사용/재배포 조건과 출처를 기록한다. 기존 음악을 복제하거나 특정 작곡가의 고유한 스타일 재현을 제작 목표로 삼지 않는다. 유료 서비스 결제·계정 가입·프로젝트 외부 업로드는 이 기획에 포함하지 않는다.

사용 가능한 음악 제작 도구가 부족하면 오프라인 합성으로 구조·반응·경고의 시제품을 만들 수 있다. 다만 단순 파형 비프·8초 코드 루프에 머무르는 결과는 최종 음질 완료가 아니다. 다층 음색, 어택/몸통/여운, 변형, 실게임 믹스로 기준을 채우거나 음악 마스터링 등 미완료 항목을 정확히 보고한다.

중간 대표 구간 검토는 빠른 수정 지점이다. 사용자가 구현을 지시했다면 단계마다 허락을 반복 요청하지 말고 기준에 따라 계속 진행한다. 품질 미달을 자산 개수나 자동 테스트 통과로 대신하지 않는다.

### 10.1 자동 검사에서 입증할 것

1. 실제 콘텐츠 ID와 사운드 매핑의 누락, 잘못된 경로, 미사용 자산, import/export 누락을 검사한다.
2. sound ON/OFF·변형 seed 차이와 무관하게 동일 입력·게임 seed의 전투/미션/드롭/점수·게임 RNG 상태가 같다. 오디오 전용 상태는 비교 대상에서 제외한다.
3. H=31→29→31→28% 및 16→14→16→21% 등 왕복에서 진입/해제 지연과 반복 제한을 지킨다. 단계 상승, 실제 pause, 최대 HP 변경도 포함한다.
4. D의 임계값 진입/완화, 실드 흡수 중 N=0, 외곽 손상만 높은 상태를 각각 검사한다. 체력 손상과 자연 붕괴가 서로의 경보로 잘못 변환되지 않는다.
5. one-shot 포화·100개 동시 XP·복수 조합 진화에서 상한/대표음/경고 슬롯과 큐 폐기를 확인한다. 음소거 해제 때 과거 사건이 재생되지 않는다.
6. 재해 10초/3·2·1초, 번개 1.5초·폭발 1.6초, 필드 아이템/파츠 10초 잔여, 미션 실제 상태, 600초 종료를 원래 게임 시각과 대조한다. 시간 경계를 여러 개 건너뛰어도 catch-up 폭주가 없다.
7. 모든 입력 경로의 확인·강화·스킬 성공이 1회만 울리고 취소된 터치/잠금/쿨다운 실패는 성공음을 내지 않는다.
8. 옛 저장·음소거·BGM OFF·손상된 음량 값, 고스트 관전/seek/배속/정지/종료를 확인한다. 플레이어 실제 프로필 대신 격리된 fixture를 쓴다.
9. 전체 기존 회귀를 현재 `tools/build.ps1` 절차로 실행하고, 관련 UI/모바일/렌더 검증을 포함한다. 새 오디오 검사는 성공 토큰과 실패 수까지 판독한다.

### 10.2 실제로 듣고 평가할 장면

| 장면 | 귀로 확인할 기준 |
| --- | --- |
| 메뉴·준비·카드·설정의 키보드/마우스/터치 | 한 조작 한 소리, 포커스 이동과 확정 구별, 재배치 때 불필요한 클릭음 없음 |
| 0~60초의 자연 전투 | 8초 반복이 드러나지 않는 음악 호흡, 자동포/명중/XP가 음악에 묻히지 않음 |
| 3전장의 같은 전투 상태 | 음악 정체성은 같고 공간 질감은 다름, 환경음이 가짜 재해 예고처럼 들리지 않음 |
| 파츠 3종·I/II 조합·12아이템 등급 | 일시 보급과 장착 파츠, 수리와 흡수막, A급 보상을 구별 |
| 4~8분의 전 무장·정예/지휘체 | 무기 계열이 구별되고 대량 처치도 연속 소음 벽이 되지 않음 |
| 낮은 HP와 높은 붕괴율을 각각 단독으로 | 설명 없이 ‘기체 상태’와 ‘환경 악화’의 원인이 다르게 들림 |
| 치명 HP+외곽+번개/블랙홀+미션 성공 | 즉시 대응할 위험이 먼저 들림, 보상 소리에 회피 경보가 가려지지 않음 |
| 강화·ESC·전투 중 도감·탭 전환·복귀 | 정지 중 유령 전투음/만료음 없음, 복귀 클릭·loop 중복·위상 어긋남 없음 |
| 5분 돌파·600초·미돌파 종료·관전 | 계속 전투/최종 결과가 구별되고 관전이 실제 업적/획득처럼 울리지 않음 |
| BGM OFF·낮은 음량·모노·모바일 스피커·헤드폰 | 핵심 경고와 조작 피드백이 남고, 한쪽/저역 의존으로 정보가 사라지지 않음 |

청취 품질표는 정체성·타격감·성장 만족·위험 식별·장시간 피로·음악 반복감의 6항목, 각 5점이다. 첫 납품 통과는 항목별 4점 이상과 치명 결함 0을 목표로 한다. 점수에는 청취 장치·설정·관찰한 장면·판단 주체를 붙인다. 구현자의 평가와 사용자의 실제 수용은 별도다.

치명 결함: 위험 경고 누락/지연, 소리만으로 잘못된 피해·보상 안내, 반복 클릭/알람 폭주, mute 무시, 심한 clipping, pause/replay의 유령 소리, 게임 결과·저장 손상, 신규 오디오로 발생한 반복적인 프레임 정지.

사운드 ON 상태로 실제 10분 한 판을 연속 청취한다. 자동으로 생성한 waveform이나 Dummy 드라이버 실행은 청취 증거가 아니다. 직접 청취가 불가능한 실행 환경이면 재현 가능한 오디오 포함 플레이 캡처를 남기고 그 항목을 미검증으로 보고한다.

### 10.3 성능·배포와 최종 보고

같은 장치·해상도·동일 시드/상태에서 음소거/새 사운드 ON을 준비 구간 후 3회 비교한다. 현재 고밀도 기준(적 240·탄 240·XP 300과 해당 기체에서 실제 가능한 설치물/위험)을 활용한다. 메인 스레드의 오디오 호출 비용, 프레임 p95/p99/max, 활성 voice, 오디오 drop, RAM, 다운로드 크기를 기록한다. 오디오 스레드 비용은 메인 스레드 호출 시간과 구분한다.

추가 오디오 제어의 메인 스레드 p95 0.5ms 이내, 전체 프레임 p95 악화 5% 이내를 초기 비교 목표로 둔다. 이는 기존 제품의 성능 목표를 낮추거나 저사양 지원을 보증하는 기준이 아니다. 오디오 활성화로 최초 발사/새 자산/장면 전환에서 생기는 순간 정지와 소리 끊김도 별도로 검사한다.

완료 보고는 **구현된 cue·실제 제작 자산·자동 회귀·청취 결과·실장치 성능·Windows/Web export/실행·사람 수용·배포 정리**를 구분한다. Windows/Web 정상 후보의 필수 검사·내보내기·실행·SHA-256 대응 확인 전에는 기존 최신본을 교체하지 않는다. 성공 후 이전 최신본을 포함한 구배포·대응 증거·임시 백업을 정리하고 최신 검증 완료 한 세대만 남긴다. 차단되면 정확한 남은 경로/이유를 기록한다. 소스·과거 설계·플레이어 저장/설정은 정리 대상이 아니다.

## 11. 구현 모델에 전달할 지시

복사해서 사용할 실행 지시는 [SOUND_IMPLEMENTATION_PROMPT.md](SOUND_IMPLEMENTATION_PROMPT.md)에 있다. 구현 모델은 실제 착수 시 변경된 소스/규칙/배포 상태를 다시 확인하고 이 계획을 적용한다. 일반적인 구현 선택을 이유로 새 대규모 설계 질문을 반복하지 않는다.

이번 기획의 산출물은 이 명세와 실행 프롬프트다. 실제 음원 제작·엔진 수정·빌드·청취·공개 배포는 수행하지 않았으며, 후속 구현 단계의 작업이다.
