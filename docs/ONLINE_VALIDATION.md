## 실제 웹 협동과 고스트

로컬 개발 서버와 실제 웹 내보내기 두 탭에서 협동 경기를 시작해 정상 결과까지 진행했다. 모델상 생존7분34초·팀28,569점이며 서버 경기 ID는 `33ca416d5e54568cfe7db19556a7275a`다. 합성 단축 fixture가 아닌 일반 협동 서버를 사용했다. 대체로 정지 상태와 강화 자동 선택을 사용했고 사람의 협동 실력/밸런스 승인을 대신하지 않는다.

이 장기 경기는 치명적 적 탄환의 구조 대기 전환 수정 전 자료다. 실제 기록 저장·고스트 호환성의 회귀 자료로 보존하며, 최종 전투 생존 시간이나 밸런스 검증으로 재사용하지 않는다. 수정 후 3전장 모델상10분 합성 검사12항목을 다시 통과했다(`soak-final.log`, 오류 로그 비어 있음).

## 최종 후보와 성능

전체 검사에는 Python17, 온라인 모델/UI/이력/생명/사망/선택/재생/연습, 실제 전용 PCK 시작, Node6 서비스 검사, 기존 게임·밸런스·아트·렌더링441·메뉴107400·오디오 검사를 포함한다. 최종 Windows EXE의 headless 시작/강제 종료는 exit0이다. `--quit-after`에서는 ObjectDB4개/자원2개의 해제 경고가 발생했으며 release EXE의 실제 입력 조작이나 깨끗한 사용자 종료 증거와 구분한다. 같은 최종 Web 파일을 별도 로컬 정적 서버와 실제 브라우저에서 시작해 메뉴·온라인 출격 버튼 렌더링을 확인했다(`final-web-start.png`). 검증용 브라우저/서버는 검사 후 종료했다.

- Web PCK: `B39C4F5C40092AD752AE55D96779CE91FDED35DA20F80CA82AFB136886B9F6B5`

성능 검사에서는 적240·탄환240·경험치300·고스트 기록이 있는 600프레임을 사용한다. 최초 단독 결과 p95 10.768ms(`performance-final.log`)는 60Hz 예산16.667ms를 통과했으나 초기값 대비 퇴행 목표를 넘었다. 같은 조건의 코드 비교에서도 수정 전 기준9.257ms/현재10.293ms, +11.19%였다(`performance-before.json`). 공격력 계산이 기존 프레임당1회에서 적마다1회로 늘어난 것을 확인했다. 싱글 경로에서 프레임당 한 번 계산한 값을 공통 접촉 판정에 전달하도록 복구했고, 협동 호출은 기존처럼 각 참가자의 현재 공격력을 전달한다. 전투 수식·순서·보상은 변경하지 않았다.
