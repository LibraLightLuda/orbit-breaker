> 최신 실제 실행 결과: [Sites 구현·검증 보고서](SITES_IMPLEMENTATION_REPORT.md). Sites 비공개 게임/랭킹/고스트/WSS를 실증했고, Sites 내부의 서버 권위 전투 실행은 별도 차단 조건으로 남는다.

> 2026-10-17 실행 순서 변경: 현재 최상위 목표는 Sites 단독 운영이다. [Sites 중심 재검토의 P0~P3 및 S0~S8](SITES_ARCHITECTURE_REVIEW.md)을 먼저 따른다. 아래 진행 상태는 기존 구현 증거이며, 외부 Linux 호스트 확보/GitHub 공개를 자동으로 다음 단계로 실행하지 않는다.

## 구현 인계

공유 전장은 `scripts/online_world.gd`, 권위 서버는 `server/match_server.gd`, 방/API/재전송은 `server/gateway.mjs`다. `server/ranking/`은 Sites 전체 원본·고정 프로젝트 ID·D1 마이그레이션이다. 새 Sites를 생성하지 않는다. 공통 웹/Windows UI·통신·예측·고스트는 `scripts/online_*.gd`다. 개인 이력은 SaveStore의 `online_records`에만 추가한다.

클라이언트 점수를 공식 결과로 받지 않는다. 비밀 키는 서버 환경에만 둔다. 닉네임을 사용자 ID로 쓰지 않는다. 같은 경기의 다른 결과는 거부한다. 장애를 로컬 경기로 이어서 공식 기록을 만들지 않는다. 완료 결과는 업로드 전에 디스크에 남긴다. 협동 전장 시간/스폰은 틱당 한 번만 진행한다. 강화 중 양쪽 예측을 정지하고 이전 선택 버전 응답은 거부한다. 연습 고스트는 싱글 성장/공식 순위를 변경하지 않는다.

## 남은 실행 순서

1. 최종 후보 manifest·검사 로그·Windows headless 실행·웹 브라우저 결과를 `ONLINE_VALIDATION.md`에 기록했다. 상대 성능≤10% 기준은 반복 계산 제거 후 동일 조건 비교에서 +2.08%로 통과했다. 이후 전체 빌드/837소스·21산출물 해시 일치를 다시 확인했다. 기존 공개본은 교체하지 않는다.
2. Linux 호스트 SSH 접속과 HTTPS 도메인을 확보한다. Node 24·Caddy·전용 사용자·데이터 경로·서버 환경을 구성하고 서버 후보를 실행한다.
3. 2방 제한으로 시작하여 실제 웹↔웹, Windows↔Windows, 웹↔Windows를 각각 완주한다. 강화/분기·구조·최종 작전·단절·관전·연습을 확인한다.
4. 위 지연/성능 기준과 12h 실행, Sites 장애 재시도, 프로세스 종료, 용량 제한을 검사한다. 50명은 목표이며 검증 전 25방으로 올리지 않는다. 실물/Safari·사람 협동 증거를 별도로 남긴다.
5. 독립 위치 일일7/주간4 백업 일정과 실제 복구 시간을 검증한다. 메타데이터 백업과 R2 고스트 보존을 구분한다.
6. `OnlineConfig.API_URL`을 실제 HTTPS 주소로 설정한 뒤 동일 소스로 웹/Windows를 다시 빌드한다. 필수 검사와 후보 실행 성공 후 GitHub Pages/Release를 교체하고 공개 파일 SHA-256·실제 플레이를 확인한다. 마지막에 보관 정책대로 구버전 배포/임시 자료를 정리한다.

새 사실에 따른 변경은 설계와 검사에 함께 반영한다. 고스트 5Hz와 개인 미션은 현재 구현에 맞춰 명시적으로 조정한 v1 결정이다. ChatGPT 로그인·영구 게스트 인증은 도입하지 않는다. 공개 전투 서버 없이 전체 서비스 완료로 표시하지 않는다.
