# Orbit Breaker 온라인 확장 — 문서화부터 구현·공개 검증까지의 최종 실행 계획

## 1. 목표와 확정 기준

현재 작업본 **3.19 / clarity-20261016**을 기준으로 기존 게임을 보존하면서 다음 서비스를 완성한다.

- **웹 배포:** 기존 GitHub Pages 주소에서 브라우저로 실행한다.
- **프로그램 배포:** GitHub Releases에서 Windows 실행 파일을 제공한다.
- **익명 랭킹:** 게임에서 닉네임과 경기 결과를 게시하는 방식으로 Sites에 기록한다. ChatGPT 로그인·계정 정보·사용자 토큰을 요구하지 않는다.
- **온라인 고스트:** 실제 서버 경기의 기록을 저장하고 관전하거나 연습 경쟁에 사용한다.
- **2인 협동:** 웹↔웹, Windows↔Windows, **웹↔Windows 교차 플레이**를 모두 지원한다.
- **운영:** 월 인프라 예산 약 10만 원을 우선하고, 실제 검증된 전투 수용량까지만 입장시킨다. 동시 접속 50명은 목표이며 초기 보장 수치로 표시하지 않는다.

기존 혼자하기·게임 규칙·콘텐츠·저장·고스트 호환성·모바일 조작·사운드를 회귀 기준으로 삼는다. 기존 미커밋 변경은 작업 기준에 포함해 보존한다.

**현재는 계획 모드이므로 문서 작성·코드 수정·배포를 실행하지 않았다. 계획 모드 해제 후 아래 순서로 문서화부터 실제 서비스 검증까지 진행한다.**

## 2. 서비스 구성과 구현 계약

### 배포와 서버 역할

| 구성 | 책임 |
|---|---|
| GitHub Pages | Godot 웹게임 파일 제공 |
| GitHub Releases | Windows 실행 파일과 안내·체크섬 제공 |
| 공통 게임 API·방 관리 서비스 | 익명 접속, 방 생성·참가, 연결 복구, 입장 제한, 결과 전달 |
| Godot headless 전투 서버 | 공식 솔로·협동의 전투, 난수, 선택지, 피해·보상·결과 판정 |
| Sites + D1 | 익명 경기 기록, 순위, 시즌, 고스트 메타데이터 |
| R2 객체 저장소 | 온라인 고스트 본문 저장과 전달 |

웹과 Windows는 같은 게임 API와 전투 서버에 접속한다. 온라인 핵심 코드는 공통 GDScript로 구현하고, 브라우저 전용 코드는 웹 입력·화면 기능에 한정한다.

Sites의 랭킹 API에는 로그인 없이 경기 게시를 요청할 수 있다. 브라우저에서 직접 호출하는 데 필요한 접근 설정이 지원되면 직접 연결하고, 지원되지 않으면 공통 게임 API가 전달한다. 어느 경우에도 클라이언트에 Sites 운영자 권한이나 데이터베이스 비밀키를 넣지 않는다.

초기 전투 서버는 Linux 서버 한 대에 배치하고 **경기당 Godot 프로세스 하나**로 시작한다. 작은 Node.js 서비스가 방·정원·프로세스·결과 재전송을 관리한다. 추가 분산 구성은 실제 수용량 측정 결과가 필요할 때 도입한다.

### 익명 랭킹

랭킹을 이용자 계정에 귀속시키지 않고 **경기 기록 단위의 익명 게시판**으로 구현한다.

- 닉네임은 중복을 허용하는 표시 이름이다. 같은 닉네임의 기록을 같은 사람으로 합치지 않는다.
- 랭킹용 게스트 계정·복구 코드·장기 사용자 세션은 만들지 않는다.
- 개인 최고와 플레이 이력은 기존 기기에 보관한다. 웹과 프로그램 사이의 자동 개인 기록 통합은 초기 범위에서 제외한다.
- 경기 ID로 중복 게시를 방지한다. 방과 연결의 임시 식별 정보는 해당 경기 통신에만 사용한다.
- 게시한 기록의 사용자 계정 기반 수정·삭제 기능은 만들지 않는다. 운영자의 기록 숨김·삭제·차단 기능은 제공한다.

**익명 게시와 점수 검증은 별개로 처리한다.** 공식 순위에는 전투 서버가 결과를 확인할 수 있는 경기만 반영한다. 사용자가 보낸 점수 숫자만으로 공식 기록을 확정하지 않는다. 기존 오프라인 기록은 로컬에 보존한다.

기본 순위는 `시즌 × 규칙 버전 × 솔로/협동 × 난이도 × 전장`으로 구분하고 기체 필터를 제공한다. 점수, 생존 틱 순으로 정렬하며 두 값이 같으면 공동 순위로 표시한다. 시즌은 한국 시간 기준 월 단위이고, 경기 시작 시점의 시즌에 귀속한다. 종료 후 24시간의 저장 유예 뒤 확정한다.

### 공개 인터페이스

| 인터페이스 | 핵심 동작 |
|---|---|

저장하는 기록에는 경기 ID, 닉네임, 점수·시간, 모드·난이도·기체·전장, 시즌·규칙 버전, 접수 시각, 고스트 참조·검증 상태를 포함한다.

서버 전용 업로드는 공개 익명 게시와 별도의 권한으로 보호한다. 입력 크기·유한값·허용 ID·요청 빈도를 검사하며, 데이터베이스에 직접 쓰는 권한은 서버 내부에 둔다.

## 3. 전투·협동·고스트의 동작

### 전투 모델과 통신

전장 공통 상태와 플레이어 상태를 분리하되 기존 1인 `RunModel` 진입점과 저장 호환성을 유지한다.

- 전장 공통 상태에는 시간·적·위험·드롭·재해·보스·팀 결과를 둔다.
- 플레이어 상태에는 위치·체력·돌진·무기·강화·진화·분기·버프·개인 미션·통계를 둔다.
- 공격·설치물·피해·획득에 소유자 또는 대상 식별자를 추가한다.
- 전장과 적은 한 틱에 한 번만 진행한다. 두 플레이어 각각에 기존 전투 전체를 실행하지 않는다.
- 1인 구성의 난수 호출 순서·보상·전투 시각을 고정 입력 회귀로 비교한다.
- 온라인에서는 이동·돌진을 예측 표시하고 서버 상태로 보정한다. 피해·획득·점수는 서버가 확정한다.
- 서버는 위치·소유자가 붙은 의미 이벤트를 전달하고, 클라이언트가 기존 효과와 소리를 재생한다.

초기 통신 기준은 서버 60Hz, 입력 최대 60Hz, 상태 전달 20Hz다. WSS를 먼저 검증한다. 지연·손실 조건에서 조작감 기준을 충족하지 못하면 서버 권위 구조를 유지하면서 WebRTC를 검증한다. 네이티브 확장과 Linux 서버 호환성까지 통과한 방식만 채택한다.

프로토콜에는 버전, 입력 순번, 이동·돌진 방향, 버튼 실행 ID, 선택 창·선택지 ID, 서버 틱, 처리 입력, 객체 생성·제거, 결과 상태를 포함한다. 클라이언트가 임의 위치·피해·점수를 확정하는 메시지는 받지 않는다.

### 협동 규칙

협동은 별도 `coop-v1` 규칙으로 관리한다.

| 영역 | 초기 구현 기준 |
|---|---|
| 기본 전투 | 기존 기체·전장·진화·분기·600초 종료 유지, 아군 피해·기체 충돌 없음 |
| 적 목표 | 가까운 생존 플레이어를 선택하고 공격 예고가 시작되면 발동까지 목표 고정 |
| 적 등장 | 두 생존 플레이어 모두에 대해 안전거리 검사 |
| 난도 | 등장 빈도 1.2배, 적 체력 1.6배. 피해·이동·위험 예고는 기존 기준 |
| 압박·상한 | 파츠 기반 압박은 참가자 평균 사용, 도중 사망으로 낮추지 않음. 개체 상한은 기존 값에서 시작 |
| 팀 점수 | 적 사망 한 번에 보상 한 번. 최종 공격 소유자의 위험층·버프 적용 |
| 경험치 | 객체 한 번 회수 후 생존자 각각에게 지급. 각자의 위험층·버프를 한 번 적용 |
| 아이템·파츠 | 아이템은 첫 접촉자, 공용 탐사 파츠는 두 참가자, 개인 미션 파츠는 소유자에게 지급 |
| 미션 | 미션·시각은 공통, 진행·보상은 개인별. 처치형은 최근 5초 유효 피해 참가자에게 인정 |
| 행성 방어 | 생존자 한 명 이상이 원 안에서 연속 12초 유지하면 한 번 성공 처리 |
| 최종 작전 | 두 사람 동의 시 도전, 무응답·불일치는 생존 계속 |
| 종료 | 전원 행동 불능 또는 600초. 팀 돌파·결과를 판정 |

강화 선택은 전장을 함께 멈추고 해당 플레이어들이 동시에 고른다. 강화 20초·분기 15초 뒤에는 제시된 회복 선택지, 없으면 첫 선택지를 자동 선택한다. 선택지 추첨은 반복하지 않는다.

수동 정지는 상대 동의 후 한 번 최대 30초, 방 전체 누적 60초로 제한한다. 개인 설정을 열었을 때 전장은 계속 진행한다.

체력 0이면 15초간 구조 가능 상태가 된다. 동료가 64px 안에서 3초 유지하면 최대 체력 30%와 전투 무적 2초로 복귀한다. 이탈·돌진·전투 피격은 구조 진행을 초기화한다. 플레이어당 한 번 구조받을 수 있으며 이후 사망하거나 구조 기한을 넘기면 관전한다. 구조할 생존자가 없으면 종료한다.

협동 전적은 기존 솔로 해금·업적 통계와 별도로 관리한다.

### 연결 장애와 결과 저장

방은 최대 2명이며 시작 후 새 참가자를 받지 않는다. 로비는 10분, 경기 실제 경과시간은 30분 상한을 둔다.

입력이 끊기면 중립화하고, 연결 장애가 확인되면 전투 전체를 정지한다. 재접속 정지는 플레이어당 누적 30초까지 허용한다. 기한 초과나 전투 프로세스 장애는 경기 중단으로 처리한다. 초기 버전은 중간 전투의 서버 장애 복원을 제공하지 않는다.

완료 결과는 먼저 서버 디스크에 기록한 뒤 Sites에 전달한다. 같은 경기의 재전송은 한 번만 반영한다. 고스트 업로드가 늦어져도 검증된 결과는 보존하고 처리 상태를 표시한다. 브라우저나 프로그램 종료 후에도 완료 기록을 조회할 수 있어야 한다.

### 고스트와 UI

기존 로컬 고스트 판독기를 보존하고 온라인에는 버전 있는 청크 형식을 추가한다.

- 실제 서버 전장 5Hz, 플레이어 궤적 20Hz를 기준으로 기록한다.
- 생성·소멸 이벤트는 발생 시점에 기록하고 짧은 객체의 누락을 방지한다.
- 두 플레이어, 소유권, 미션·분기·최종 작전·보호장치·결과를 포함한다.
- 2초 청크와 해시·완료 매니페스트를 사용한다. 청크당 압축 1MiB·해제 4MiB, 전체 압축 64MiB 제한에서 시작한다.
- 불완전·손상·초과 자료는 재생 가능 상태로 노출하지 않는다.
- 기존 배속·정지·탐색을 재사용하고 협동 시점 전환을 추가한다.
- 고스트 경쟁은 같은 초기 설정·시드를 사용하는 연습 도전으로 제공한다. 상대 고스트는 충돌·보상에 관여하지 않으며 공식 일반 순위에는 등록하지 않는다.

메인 흐름은 혼자하기·온라인 도전·2인 협동·기록으로 통합한다. 기존 시각 언어와 사운드를 재사용하고 핵심 선택은 세로 스크롤 없이 배치한다. 결과 화면에는 닉네임 입력, 등록 상태, 고스트 처리 상태를 제공한다. 회전·네트워크 재시도로 선택 상태를 잃지 않게 한다.

## 4. 실행 순서와 검증 기준

| 단계 | 의존성 | 작업 | 완료 기준 |
|---|---|---|---|
| **P0 문서화** | 현재 작업본 | 설계·작업·운영 문서 작성, 기존 소스·배포 기준 기록 | 이 계획의 모든 요구사항과 진행 상태를 문서에서 추적 |
| **P1 기술 실증** | P0 | Sites 익명 쓰기·서버 업로드·백업 복원, Linux 실행, 웹↔Windows 통신 | 실제 환경에서 플랫폼·전송·비용 구성 확정 |

선행 통신 검사는 실제 웹 한 개와 Windows 실행 파일 한 개로 수행한다. RTT 80ms·지터 20ms·손실 1%에서 입력 처리 지연 p95 150ms 이하, 본인 위치 보정 오차 p95 13px 이하·p99 52px 이하를 목표로 한다. 더 나쁜 조건에서는 경고·재접속·중단을 검증한다.

실제 서버에서 최대 밀도·고스트 기록을 포함한 후보 입장 상한을 측정한다. CPU 여유 30% 이상, 메모리 70% 이하와 지속적인 틱 밀림 없는 상태를 기준으로 하고, 12시간 실행으로 지속 성능을 확인한다.

필수 검사에는 다음을 포함한다.

- 기존 전체 회귀와 동일 장면 솔로 성능 p95 10% 이내 퇴행 기준.
- 모든 기체·전장·난이도·진화·분기·보스·최종 작전.
- 동시 처치·획득·강화·사망, 구조 중 피격, 중복 참가·시작.
- 변조 입력·초대형 요청·대량 게시·타인 경기 요청·중복 결과.
- Sites·저장소 장애, 부분 고스트, 프로세스 종료, 배포 중 연결.
- 구형 저장·고스트, 저장 공간 부족, 회전·백그라운드·새로고침.
- 실제 Windows, 데스크톱 주요 브라우저, Android Chrome·iOS Safari.
- 두 사람의 조작감·강화 대기·구조·협동 난도 평가.

## 5. 운영·인계·최종 완료 조건

문서는 다음 세 파일로 관리한다.

- `docs/ONLINE_SERVICE_DESIGN.md`: 채택 구조, 익명 게시 모델, 전투·협동·고스트 계약과 설계 결정.
- `docs/ONLINE_IMPLEMENTATION_PLAN.md`: 단계별 작업·의존성·검사 결과·남은 문제.
- `docs/ONLINE_OPERATIONS.md`: 배포·버전 호환·시즌·백업 복원·장애·입장 및 비용 제한.

Sites에서 외부 익명 API 또는 백업 복구를 충족하지 못하면 같은 API와 데이터 구조를 독립 Cloudflare Workers·D1·R2로 옮기는 대안을 사용한다. Sites 채택 여부는 P1에서 확정하고 결과를 문서에 남긴다.

경기·시즌 기록은 유지하고 일반 고스트는 7일, 현재 시즌 최고 고스트는 시즌 동안, 종료 시즌 최고 고스트는 90일 보관한다. 고스트 만료 후에도 점수는 남긴다. 일일 백업 7개·주간 백업 4개를 암호화해 독립된 위치에 보관하며 복구 목표는 RPO 24시간·RTO 4시간 이하다.

배포는 정상본 보존, 후보 검사, 기존 경기 종료 대기, 새 버전 전환, 실제 주소 확인 순서로 진행한다. 성공 후 이전 실행물·대응 증거·임시 백업을 정리하여 최신 검증 완료 한 세대만 유지한다. 플레이어 데이터와 그 백업은 배포 정리 대상에서 제외한다.

최종 완료에는 문서·코드뿐 아니라 다음 결과가 필요하다.

- GitHub 공개 웹과 Windows 실행 파일의 온라인 동작.
- ChatGPT 로그인 없이 등록·조회하는 실제 랭킹 서비스.
- 웹↔Windows를 포함한 세 조합의 협동 완주.
- 실제 경기 고스트의 저장·관전·경쟁.
- 중복 저장·장애·복원·입장 제한 검증.
- 배포물·소스·검증 자료의 버전과 해시 대응.
- 운영자가 재배포·시즌 종료·백업 복구를 수행할 수 있는 안내.

외부 호스트·권한·비용 설정이나 실물 기기가 필요한 단계에서는 준비된 코드와 실제 운영 검증 상태를 구분해 기록한다. 막힌 단계 외의 구현과 검사는 계속 진행한다.

현재 확인은 기존 작업본과 배포 설정까지이며 실제 구현·배포는 시작하지 않았다. 주요 잔여 위험은 Sites의 익명 API 운영 가능성, 교차 플레이의 조작감, 예산 안에서의 전투 수용량이다.
